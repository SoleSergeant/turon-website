Projects section: round 2

Four new concepts built from the research: one short line + a status per project (Hack Club), never overcrowd (nonprofit guides), lists read best on phones, keep card sizes equal (bento caveat), and treat each project as a sub-brand of Turon (parent-brand portfolios). Brand colours only.

Concept E

Tiles on laptops, list on phones

One piece of markup, two layouts. On wide screens each project is a solid tile in its colour. Under 760px the same items turn into a compact list with a colour bar, so phones never need a sideways swipe. Narrow the window to see it switch.

list vs grid research (lists read faster), parent-brand portfolios (one colour per brand).

Concept F

One spotlight, everything else equal

A full-width banner for the one project with something to do right now, then every project (spotlit one included) as equal cards below. Only two sizes ever exist, so adding projects never breaks the layout.

bento-grid caveat (avoid hand-sized cells), "one clear path" from nonprofit homepage guides.

Concept G

Sub-brand lockups

Each card looks like a small version of the project's own site header: "turon." above the project name, in the project's colour. It tells visitors that every project is part of one family, and the card footer shows exactly where the link goes.

parent-brand portfolio pages (Virgin, Gap), AIESEC's "always show the parent name" rule.

Concept H

Grouped by status

Projects sorted into "Active" and "Coming soon", each a compact row with a coloured initial. As projects are added or finish, they move between groups (a "Past" group can be added later), and each group stays short.

Hack Club's status tags on programs, "avoid overcrowding" from nonprofit guides.
